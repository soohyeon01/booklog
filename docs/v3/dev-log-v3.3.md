## 🛠️ 기술적 예외 처리 및 트래픽 기록 (Troubleshooting)

### 📌 2026.10.15 - 신규 경로가 로그인 인터셉터 적용 범위 밖에 있던 문제 (사전 점검)
- **증상(예상)**: `/stats`, `/history`를 추가해도 `LoginCheckInterceptor`가 `/books/**`에만 걸려 있어, 비로그인 상태로 접근하면 로그인 화면으로 이동하지 않고 `@LoginMember`로 주입되는 `memberId`가 `null`이 됨.
- **원인**: 인증 경로가 기능 단위가 아닌 `/books/**` 한 패턴에 묶여 있어, 컨트롤러가 늘어날 때 경로를 함께 등록하지 않으면 보호 대상에서 빠짐.
- **해결**: 구현 전에 인터셉터의 `addPathPatterns`에 `/stats/**`, `/history/**`를 추가.
- **성과 및 배운 점**
    - 새 화면을 추가할 때는 기능 구현과 별개로 "이 경로가 인증·인가 범위 안에 있는가"를 확인하는 단계가 필요함을 체감함.

### 📌 2026.10.15 - 이력 화면 추가로 인한 삭제 로직 중복
- **증상**: 독서 기록 삭제 메서드가 `deleteLog`(상세 화면용)와 `deleteLogFromHistory`(이력 화면용) 두 개로 나뉘어 같은 일을 하는 코드가 중복됨.
- **원인**: 이력 화면의 삭제 URL에는 `bookId`가 없어 기존 `deleteLog(bookId, logId, memberId)`를 호출할 수 없었고, 기존 메서드를 정리하지 않은 채 새 메서드를 덧붙임. 두 메서드는 기록을 찾는 방법만 다르고 소유권 검증이라는 규칙은 동일했음.
- **해결**: `logId`와 `memberId`만으로 "내 책에 속한 기록"을 한 번에 조회하는 `findByIdAndBookMemberId`로 검증을 통일하고, 삭제 메서드를 `deleteLog(logId, memberId)` 하나로 합침. URL의 `bookId`는 삭제 후 상세 화면으로 돌아가는 주소에만 사용.
- **성과 및 배운 점**
    - 새 기능을 위해 메서드를 추가하기 전에 기존 메서드의 입력 조건을 일반화할 수 있는지 먼저 검토해야 하며, 같은 규칙을 두 곳에서 유지하면 한쪽만 고치는 실수가 생길 수 있음.
    - 소유권 검증을 두 번의 조회(책 확인 + 기록 확인)에서 한 번의 조인 조회로 줄여 쿼리 수까지 개선됨.
