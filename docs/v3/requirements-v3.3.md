# 📚 북로그(BookLog) v3.3 스펙 명세서 & 개발 일지

## 📋 스펙 명세

> v3.3은 v3.1에서 쌓은 독서 기록(`readingDate`)을 활용해 **독서 통계 대시보드**와 **개인 독서 이력** 화면을 추가한 버전입니다.
> 쿼리 최적화(v3.2)는 아직 진행하지 않았으며 v3.3 이후로 이어집니다. 본 버전에서 추가한 집계·이력 쿼리도 v3.2의 최적화 대상에 포함됩니다.

### 1. 독서 통계 대시보드 (`GET /stats`)

* **요약 카드**: 전체 도서 수, 누적 독서 기록 수, 이번 달 기록 수, 평균 평점 (평점이 없는 도서는 평균에서 제외)
* **월별 독서량**: 최근 12개월을 기준으로 월별 **기록 수**와 **기록이 있는 책 수**(중복 제거)를 집계
    * 페이지 수 필드가 없으므로 독서량을 기록 수·책 수로 정의
    * 집계 기준은 작성 시각이 아니라 사용자가 지정한 읽은 날짜(`readingDate`)
* **독서 상태 비율**: `WISH` / `READING` / `DONE`별 도서 수
* **평점 분포**: 1~5점별 도서 수
* **자주 쓴 태그 TOP 5**: 도서 수 기준 상위 5개 태그, 태그를 클릭하면 키워드 검색(`/books?keyword=`)으로 연결
* **집계 방식**
    * 통계 값은 애플리케이션에서 전체 데이터를 순회해 세지 않고 **DB의 `GROUP BY` 집계 쿼리**로 계산하고, 결과는 `select new`로 DTO(record)에 바로 담음
    * 기록이 없는 달, 도서가 없는 상태, 사용되지 않은 평점은 DB 결과에 나타나지 않으므로 서비스 계층에서 0으로 채워 차트가 끊기지 않도록 함
* **차트**: Chart.js(CDN, 버전 고정)로 렌더링하고, 데이터는 Thymeleaf JavaScript 인라이닝으로 전달
* **회원별 격리**: 모든 집계 쿼리는 로그인 회원의 `memberId` 조건을 포함 (독서 기록은 `book`을 조인해 `book.memberId`로 제한)

### 2. 개인 독서 이력 (`GET /history`)

* 로그인 회원의 **모든 독서 기록을 책 구분 없이 최신순**(`readingDate` 내림차순, 같은 날짜는 `id` 내림차순)으로 조회하고, 월 단위로 묶어 표시
* **월 필터**: `?month=yyyy-MM` (미지정 시 전체)
* **페이징**: 페이지당 10건 (`?page=`)
* 각 기록에서 해당 도서 상세 화면으로 이동 가능
* **기록 삭제**: `POST /history/{logId}/delete`, 삭제 후 **보던 월 필터와 페이지를 유지**한 채 Redirect(PRG 패턴)
* **조회 최적화**
    * 기록마다 책 제목을 지연 로딩하지 않도록 `join fetch`로 도서를 함께 조회 (to-one 관계라 페이징과 함께 사용 가능)
    * 페이징용 건수 조회는 `countQuery`를 별도로 지정

### 3. 접근 제어 및 보안 요구사항

* `LoginCheckInterceptor` 적용 경로를 `/books/**`에서 `/stats/**`, `/history/**`까지 확장
    * 기존 인터셉터 설정만으로는 신규 경로가 보호되지 않아, 비로그인 요청 시 `@LoginMember`로 주입되는 `memberId`가 `null`이 될 수 있음
* 독서 기록 삭제의 소유권 검증은 `findByIdAndBookMemberId(logId, memberId)` 한 번의 조회로 처리
    * 도서 상세 화면과 독서 이력 화면의 삭제가 동일한 `deleteLog(logId, memberId)`를 공유 (상세 규칙은 [v3.1 명세](requirements-v3.1.md) 3-4 참고)

### 4. 더미데이터 보강

* 통계 화면이 의미 있게 보이도록 기록이 없는 `READING`/`DONE` 도서에 **샘플 독서 기록을 도서당 1~4개** 생성
    * 랜덤 값을 쓰지 않고 도서 순번 기반으로 결정하여, 시딩할 때마다 동일한 결과가 나오도록 구성
    * 가장 최근 기록 날짜를 오늘부터 약 150일 전 사이에 도서별로 분산하고, 같은 도서의 기록은 4일 간격으로 배치 → 월별 통계가 여러 달에 걸쳐 나타남
    * `WISH` 상태 도서는 기록 없음
* 시딩 가드(`bookRepository.count() > 0`) 때문에 기존 데이터가 있으면 새 시드가 실행되지 않으므로, 관련 테이블을 비운 뒤 재시딩해야 함

### 5. 테스트 요구사항 (미완료)

* `StatsService`의 빈 구간 0 채우기, 집계 쿼리(`findMonthlyStats` 등), 이력 조회 쿼리에 대한 자동화 테스트는 아직 작성하지 않음
* 서비스 단위 테스트(Mockito)와 `@DataJpaTest` 기반 쿼리 테스트는 v3.2에서 보강 예정

### 6. 남은 작업

* **v3.2 (예정)**: 쿼리 최적화
    * 도서 목록의 저자/태그 지연 로딩 N+1 재현·해결, 목록 조회 시 중복 호출 정리, Member ↔ Book `@ManyToOne` 승격
    * 본 버전의 집계·이력 쿼리에 대한 실행 계획 확인 및 인덱스 검토
    * `@DataJpaTest` 기반 Repository 테스트로 전환
* **후보**: 독서 기록 수정 기능, 저자별 통계, 통계 기간 선택
