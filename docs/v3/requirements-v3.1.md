# 📚 북로그(BookLog) v3.1 스펙 명세서 & 개발 일지

## 📋 스펙 명세

> v3.0에서 모델링한 **Tag·ReadingLog를 실제 화면과 기능으로 연결**하고, 엔티티 변경으로 중단되었던 **더미데이터를 복구**한 버전입니다.
> 영속성 전환과 도메인 모델링은 [v3.0](requirements-v3.md)를 참고하세요.

### 1. 저자/태그 변환 로직 공통화

* 콤마로 구분된 문자열을 `Author`/`Tag` 엔티티 집합으로 변환하는 로직을 `BookRelationResolver` 컴포넌트로 분리
    * 기존에는 `BookServiceImpl`의 `resolveAuthors`와 더미데이터 초기화 코드에 동일한 로직이 중복될 위험이 있었고, 태그까지 추가되면 중복이 늘어나므로 한 곳으로 통합
* 이미 존재하는 이름이면 재사용하고 없으면 생성(find-or-create), 입력 내 중복은 제거
* 같은 트랜잭션 안에서 호출되어야 동일 이름이 같은 인스턴스로 합쳐지므로 서비스 계층의 트랜잭션 범위 안에서만 사용

### 2. 태그(Tag) 기능

* **입력**: 도서 등록/수정 폼의 태그 입력란 (콤마 구분, 선택 입력, `BookForm.tags`, 최대 100자)
* **정규화**: 앞의 `#` 제거, 공백/빈 값 제외, 30자 초과 태그는 무시
* **수정 시 동작**: 기존 태그 연결을 비우고(`clear`) 새 입력값으로 다시 매핑 — 컬렉션 인스턴스를 유지하여 변경 감지가 꼬이지 않도록 함
* **표시**: 목록 화면은 제목 아래, 상세 화면은 태그 행에 `#태그` 뱃지로 노출
* **검색 연계**: 뱃지를 클릭하면 `/books?keyword={태그명}`으로 이동하며, 키워드 검색 대상이 제목·저자에 더해 **태그명까지 확장**됨 (`searchBooks` 시그니처는 유지)
* **한계**: 태그 전용 필터가 아니라 키워드 부분 일치 검색이므로 "정확히 이 태그만"을 걸러내지는 못함

### 3. 독서 기록(ReadingLog) 기능

#### 3-1. 화면 및 엔드포인트
* **화면**: 도서 상세 하단의 "독서 기록" 섹션 — 기록 수 뱃지, 추가 폼, 최신순 타임라인 목록
* `POST /books/{bookId}/logs` — 기록 추가
* `POST /books/{bookId}/logs/{logId}/delete` — 기록 삭제
* 두 경로 모두 `/books/**` 하위이므로 기존 `LoginCheckInterceptor`가 그대로 적용되며, 처리 후 상세 페이지로 Redirect(PRG 패턴 유지)

#### 3-2. 입력 검증
* 내용은 trim 후 1~1000자
* 읽은 날짜는 미입력 시 오늘 날짜, **미래 날짜는 불가** (서버 검증 + 브라우저 `max` 속성)
* 검증 실패 시 예외 페이지가 아니라 Flash 메시지(`logError`)로 상세 화면에서 안내

#### 3-3. 날짜 설계 결정
* 기록 날짜를 **작성 시각 자동 기록(`@CreatedDate`)이 아닌 사용자 지정 읽은 날짜(`readingDate`, `LocalDate`)로 확정**
* 이유: 독서 기록은 나중에 몰아서 쓰는 경우가 많아, 작성 시각으로 월별 독서량을 집계하면 수치가 왜곡됨. 날짜 단위 집계에는 시간대 문제가 없는 `LocalDate`가 적합
* 정렬: `readingDate` 내림차순, 같은 날짜는 `id` 내림차순

#### 3-4. 보안 요구사항
* 기록 추가 전에 findByIdAndMemberId로 책 소유권을 먼저 검증
* 기록 삭제는 findByIdAndBookMemberId(logId, memberId) 한 번의 조회로 "내 책에 속한 기록"인지 검증 — 다른 회원의 기록 ID로 삭제하는 우회(IDOR) 차단
  * 도서 상세 화면과 독서 이력 화면의 삭제가 동일한 deleteLog(logId, memberId)를 공유하여 삭제 규칙을 한 곳에서 관리하고 조회 쿼리를 1회로 줄임
  * URL의 bookId는 삭제 후 상세 화면으로 되돌아가는 주소에만 사용함

#### 3-5. 도서 삭제 시 기록 정리
* `reading_log`는 `Book`을 참조만 하고 `Book` 쪽에서 관계를 관리하지 않아, 도서를 삭제해도 기록이 자동 삭제되지 않고 FK 제약 위반이 발생
* 도서 삭제 전에 `deleteAllByBookId`로 해당 도서의 독서 기록을 먼저 삭제 (소유권 검증을 통과한 뒤에만 호출)

### 4. 더미데이터 구조 개선

* **`BookSeed` record 분리**: `BookDummyData`가 `Book` 엔티티 생성자를 직접 호출하던 구조를, 엔티티와 결합되지 않는 순수 데이터(`title`, `author`, `status`, `rating`, `summary`, `memo`, `tags`, `logs`)로 분리
    * 6개 인자 보조 생성자를 두어 기존 80권 항목은 형식 변경 없이 그대로 사용, 태그/기록을 직접 지정할 항목만 확장 생성자 사용
* **`TestDataInit` → `ApplicationRunner` 전환**: `@PostConstruct`는 프록시 적용 이전에 호출되어 `@Transactional`이 적용되지 않으므로, 컨텍스트가 준비된 뒤 실행되는 `ApplicationRunner`로 변경
* **중복 시딩 방지**: `bookRepository.count() > 0`이면 시딩을 건너뜀 (재시작 시 중복 삽입 방지)
* **태그 자동 추론**: 시드에 태그가 비어 있으면 제목/한줄요약의 키워드(소설, 에세이, 미스터리, 역사 등)를 태그로 매핑(최대 3개)
* **독서 기록 시드**: 책마다 가장 최근 기록 날짜를 오늘~59일 전 사이에 분산하고, 같은 책의 기록은 4일 간격으로 배치하여 월별 집계 시 여러 달에 걸쳐 보이도록 구성
* **회원 배분**: 더미 도서를 `user1`/`user2`에게 절반씩 배정 (v2.0 구성 유지)

### 5. 테스트 요구사항 (미완료)

* v3.1에서 추가된 로직(태그 변환, 독서 기록 소유권 검증, 도서 삭제 시 기록 선삭제)에 대한 자동화 테스트는 아직 작성하지 않음
* 핵심 로직(IDOR 우회 차단, 선삭제)은 v3.2에서 서비스 단위 테스트와 `@DataJpaTest`로 보강 예정

### 6. 남은 작업 및 후보

* **v3.2 예정**: Query 최적화(N+1 재현/해결, 목록 조회 시 중복 조회 정리), Member ↔ Book `@ManyToOne` 승격, `@DataJpaTest` 전환
